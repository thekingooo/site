# ПРОСТРАНСТВО

Интерактивный сайт коммерческой архитектуры: Next.js App Router, TypeScript,
React Three Fiber, Three.js, GSAP ScrollTrigger. Текст, шрифты, визуализации и
материалы доступны локально; приложение не зависит от внешних CDN.

## Запуск

Требуется Node.js 24 (проверено на 24.19.0) и npm. Версия указана в `.node-version`.

```sh
cd /workspace/site
npm ci
npm run dev
```

Сервер слушает порт 3000 на всех интерфейсах. При необходимости:
`npm run dev -- --port 3001`. Используйте существующий checkout: облачная задача
уже изолирована, создавать Git worktree не нужно.

```sh
npm test                 # 9 проверок анимации и валидации
npm run typecheck
npm run build
npm run start            # production, после сборки
npm run test:e2e         # после сборки, отдельный сервер на порту 3100
```

Браузерные тесты используют установленный Chromium: `/usr/bin/chromium`.
Для другого расположения задайте `CHROMIUM_PATH`. На локальной машине без
Chromium установите его из доверенного системного репозитория. Тесты проверяют
WebGL, все пять состояний и обратную прокрутку, инженерные слои, фильтры и страницы,
сохранение и скачивание брифа, вложения, серверную валидацию, мобильное меню,
reduced motion и fallback без WebGL. Созданные тестовые заявки удаляются тестом.

## Проверка новой офисной модели

После запуска приложения откройте путь `/model-review` в браузере. Здесь доступна
новая офисная модель с управлением камерой мышью / пальцем, масштабированием и
раздвижением инженерных слоёв. Кнопка «Открыть свой референс» показывает выбранную
картинку рядом с 3D. Файл остаётся в браузере и не загружается на сервер.

Путь `/?space=office` открывает офис непосредственно в основной scroll-сцене.

**Состояние визуальной доработки:** заменены общая оболочка, основание, инженерный
верхний слой и офис. Кафе, ритейл, банк и клиника сохраняют предыдущие процедурные
интерьеры. Новая сцена — первая итерация по загруженному офисному референсу;
она не заявляется как точная копия изображения. Новый референс продуктового
магазина отличается от прежнего fashion-бутика; лобби отеля требует уточнения
состава направлений перед заменой существующих сцен.

## Устройство 3D

- `public/models/architecture.glb` — настоящая геометрия оболочки с тремя
  независимыми корневыми узлами `Shell`, `Foundation`, `Engineering`.
- `public/models/office.glb` — офис с узлом `Interior`: переговорная за стеклом,
  два рабочих места, кресла, мягкая зона, растения и встроенная мебель.
- `scripts/build_architecture.py` — исходник сцены Blender, размеры в метрах,
  Z вверх. При экспорте glTF используется Y вверх. Все стороны объектов
  существуют геометрически. Инженерный узел слегка наклонён в разнесённом виде
  для лучшей видимости коммуникаций. Камера перспективная.
- Свет, непрямое освещение и контактные тени рассчитаны в Cycles и запечены в
  UV-атласы. В WebGL атласы подключены как emission к физическим материалам:
  освещение комнаты сохраняется при вращении, отражения и стекло рассчитываются
  в реальном времени. В режиме Эко стекло использует прозрачность без рефракции.
  Запечённые поверхности в Эко используют лёгкие материалы без повторного
  расчёта света; на программном WebGL этот режим выбирается автоматически.
- `scripts/finalize_model.py` удаляет шум официальной утилитой Intel Open Image
  Denoise (RTLightmap для атласов и RT для контрольного рендера).
- Meshopt сжимает геометрию без упрощения сетки; WebP сжимает встроенные текстуры.
  Декодер Meshopt поставляется с установленными Three / Drei, внешний CDN не нужен.
- `DetailedArchitecture.tsx` загружает локальные GLB через Suspense, сохраняет
  отдельные слои и нормализует оси анимации. `ExperienceCanvas.tsx` связывает
  новую архитектуру с прежними четырьмя интерьерами. `model.ts` содержит эти
  предыдущие процедурные интерьеры.
- `ScrollSceneController.tsx` использует единый GSAP ScrollTrigger, нативную
  прокрутку и `scrub: 0.65`. `timeline.ts` задаёт четыре полных оборота по часовой
  стрелке, общий индекс текста и раскрытие инженерии. Последний кадр не округляется.
- Рендер выполняется по требованию. HQ добавляет мягкое свечение светильников;
  Эко снижает разрешение и отключает постобработку. Reduced motion убирает
  вращение. При отсутствии WebGL остаются статичные визуализации.

### Воспроизведение GLB

Для запуска сайта Blender не требуется: готовые GLB уже находятся в репозитории.
Ниже — необязательный Linux-процесс для изменения самих 3D-ассетов. Проверено на
Blender 4.3.2, Intel OIDN 2.3.3 и glTF Transform 4.2.1. Установите официальную
утилиту OIDN из https://github.com/RenderKit/oidn/releases и укажите путь к
`oidnDenoise`. Не отключайте проверку TLS и целостности загружаемых пакетов.

```sh
blender -b --factory-startup --python-exit-code 1 -t 5 \
  --python scripts/build_architecture.py -- \
  --scene office --bake --atlas-size 1536 --output /tmp/prostranstvo-office

blender -b /tmp/prostranstvo-office/office.blend --python-exit-code 1 -t 5 \
  --python scripts/finalize_model.py -- \
  --directory /tmp/prostranstvo-office --oidn /path/to/oidnDenoise --render

npm exec --yes --package @gltf-transform/cli@4.2.1 -- gltf-transform optimize \
  /tmp/prostranstvo-office/architecture.glb public/models/architecture.glb \
  --compress meshopt --simplify false --flatten false --join false \
  --instance false --palette false --texture-compress webp --texture-size 2048

npm exec --yes --package @gltf-transform/cli@4.2.1 -- gltf-transform optimize \
  /tmp/prostranstvo-office/office.glb public/models/office.glb \
  --compress meshopt --simplify false --flatten false --join false \
  --instance false --palette false --texture-compress webp --texture-size 2048
```

Промежуточные `.blend`, EXR и карты освещения пишутся вне checkout. Исходные
текстурные файлы и их SHA-256 указаны в `assets/source/manifest.json`;
лицензии — в `assets/THIRD_PARTY.md`. Контрольная картинка
`public/images/office-model-review.jpg` получена из реальной модели, не сгенерирована ИИ.

## Содержимое

`src/lib/content.ts` хранит пять пространств, пять услуг и пять демонстрационных
проектов. Фильтры работают по реальным данным; у каждой концепции и услуги
есть отдельная индексируемая страница. Реальные заказчики, города, метражи,
лицензии, реквизиты и достижения не выдуманы. Шрифты Manrope и Cormorant Garamond
поставляются пакетами Fontsource с их лицензиями. Остальные концептуальные изображения
созданы с помощью image generation и хранятся в `public/images/`.

## Форма и запуск для реального бизнеса

Форма **явно демонстрационная**: `POST /api/inquiries` валидирует данные,
проверяет согласие, размер и сигнатуру вложения и сохраняет бриф на диске.
Письма, Telegram и CRM не подключены; заявка не доставляется компании.
Успешное уведомление говорит только о сохранении брифа. Пользователь может
скачать его текст. Принимаются PDF/JPG/PNG до 5 МБ, весь HTTP body ограничен
5 МБ + 64 КБ. Есть проверка origin, honeypot и ограничение частоты запросов
в памяти процесса. Для распределённого продакшена нужен общий rate limiter.

Записи: `.data/inquiries/<UUID>/brief.json` и необязательный `attachment.*`.
Каталог не публичный и исключён из Git. Не загружайте конфиденциальные данные.
Удаление тестовых записей выполняется оператором этого экземпляра из закрытого
хранилища. Автоматическая очистка не обещана и не настроена.

Опциональные переменные описаны в `.env.example`:

- `NEXT_PUBLIC_SITE_URL` — фактический публичный origin для абсолютных OG-ссылок.
- `INQUIRY_STORAGE_DIR` — закрытый постоянный том для брифов. Если серверная
  платформа имеет эфемерную или read-only файловую систему, подключите постоянное
  хранилище или замените адаптер сохранения. Не помещайте его в `public/`.

До коммерческого запуска нужны реальные контакты компании, правовые документы
оператора данных, согласованный срок хранения, подключение CRM/почты и реальные
проекты. Только после проверки доставки можно менять демонстрационные подписи.
Данные формы не выводятся в логи. Сторонних трекеров нет; для интеграции аналитики
предусмотрены локальные DOM-события `prostranstvo:interaction`
(`scene`, `scene_view`, `cta`, `inquiry`).

## Облачное окружение

Зависимости и `.next` сохраняются на диске; процессы после восстановления
снимка нужно запускать заново. Для установки требуется только npm registry и
существующая платформенная GitHub-аутентификация; секреты приложению не нужны.
Проверяйте готовность локальным HTTP-запросом и фактическим открытием страницы,
а не только наличием PID. Проверки из `tests/browser` выполняют функциональные
запросы, не требуя публичного preview или внешних сервисов.
